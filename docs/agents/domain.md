# Domain docs

This repository uses a single-context layout: a root `CONTEXT.md` and `docs/adr/` for architectural decisions.

## Before exploring

Read `CONTEXT.md` when present and any ADRs relevant to the work. If a future `CONTEXT-MAP.md` exists, follow its pointers to relevant context documents.

If these files do not exist, proceed without requiring or scaffolding them. Domain-modeling work creates them when terms or decisions need recording.

The current product scope and domain vocabulary are in `docs/spec.md`.

## Vocabulary and decisions

Use the glossary's terms in tickets, code discussions, and refactor proposals. Note meaningful vocabulary gaps rather than introducing conflicting synonyms.

Surface conflicts with existing ADRs before proceeding with a contradictory design.
